# 录制、导入与官方格式

本机 `.dmimulog` 是带版本头的 UTF-8 JSONL，保存原始接收块、主机 UTC 秒和录制相对秒；回放不会按显示倍速改写测量时间。导入不会连接设备、切换数据源或恢复文件中的设置。相同文件以 SHA-256 去重，文件只存入私有数据目录。单文件导入最多 1 GiB。

支持官方 `.imulog` 的 `IMULOG01` 容器双向转换，保留原始接收块。格式由官方 `dm-imu-upper.exe` 的 NativeAOT 读写实现核对，来源是[官方仓库](https://gitee.com/kit-miao/dm-imu)，版本参考 commit `ba758fd6106c2b210713bf1ef05800f1688f73c5`。

| 内容 | 格式 |
| --- | --- |
| 文件头 | ASCII `IMULOG01`，8 字节 |
| 元数据长度 | little-endian int32，1–16384 字节 |
| 元数据 | UTF-8 JSON：StartedUtc、Source、BaudRate、Protocol、TimeBasis |
| 数据块 | little-endian double 相对秒、int32 原始块长度、原始字节 |
| 正常结束 | double 结束相对秒、int32 `-1`、uint64 总块数 |

只接受 `Protocol="bosch-api-v1"`、`TimeBasis="host-receive-seconds"`，块长 1–65536。StartedUtc 必须有有效时区，不以当前时间冒充录制时间。导入检查顺序、结束块数与有效 CRC 数据帧；文件尾部中断可恢复此前完整块，并返回 `complete:false` 和明确警告。中间损坏、非法时间、错误完整结束标记会拒绝导入。

证据位置（对应上述官方 EXE）：magic 初始化 `0x1403fda60`；头部写入 `0x1403fd670`；块提交 `0x1403fd890`；头部读取 `0x1403fdac0`；数据扫描与结束块数校验 `0x1403fde40`。合成容器与本机格式进行了导入/导出往返测试；没有在 Windows 官方程序中实际打开本机导出的文件，因此 Windows 端最终互操作仍待验证。

Agent 示例：

```sh
python3 -S agent_cli.py recording-import --input recording.imulog
python3 -S agent_cli.py download RECORDING_ID --format imulog --output copied.imulog
python3 -S agent_cli.py action playback.open --params '{"id":"RECORDING_ID"}'
```

官方容器导出保留录制块的相对时间和原始字节。本机版头部 BaudRate 为 CDC 接入设置的兼容元数据，不是样本频率；Allan/FFT 应显式使用已知的设备输出 Fs。

## 长录制流式回放

回放不再把所有帧读进内存，也没有旧版 100 MiB／50 万帧的回放限制。官方文件导入后转换为本机原始块文件，JSONL 与 Base64 带来的文件大小增加不影响流式回放。服务只缓存稀疏索引、各通道的最新帧和一个最多 64 KiB 的原始数据块；浏览器波形缓存仍遵循独立的 90 秒上限。

打开文件时先顺序校验原始块并解码有效 CRC 帧，确认完整数据结构、原始时间顺序、总帧数和有效帧结束时间。这个阶段不会切换当前采集源；索引成功后才进入回放。大文件首次打开需要扫描整段文件，操作状态提供 `index_recording` 阶段、已扫描字节、总字节、有效帧数和进度比例。客户端应查询同一个操作 ID，不要在等待较久后重复打开。索引仅保存在本次进程内，重新打开会再次校验。

索引按照至少 256 KiB 的字节间隔建立，文件更大时自动增加间隔，将检查点数量限制在约 4096 个。每个检查点保留文件偏移、跨接收块的解码器残留，以及主从机 ID 对应显示设备各通道的最新原始帧。设备选择优先使用录制头部的明确 `slave_id`，否则采用录制里首次出现的有效帧 ID；不把其它总线设备的通道合成同一个姿态。所有设备的原始帧仍保留在文件中，并按顺序参与正常回放接收计数。

跳转使用 `[0, position]` 闭区间：相同相对时间下的所有完整块都属于该位置，跨块帧的时间取该帧完整解码时的原始块时间。服务从目标前最近检查点读取到该位置，显示每个通道最后一帧，并保存下一块用于继续播放。跳转增加数据源 generation，清空之前的波形与显示基准；跳转预览不作为惯性积分轨迹的历史。

播放每轮最多释放 4096 帧、读取最多约 1 MiB／1024 个块。突发的大批同时间戳帧继续留在有界队列，下一轮继续释放；到达结束时间也会先排完最后一批，不截断末尾数据。慢磁盘或 CPU 跟不上所选倍速时，显示数据可能暂时落后于播放游标。

播放速度只控制相对秒 `elapsed` 的推进。采样 `measurement_time` 始终是原录制的 UTC 接收秒，实时 UI 新鲜度仍使用当前服务时钟；FFT 和数据导出不会把 4× 回放变成 4× 采样频率。文件在回放中被替换或修改时停止继续读取，并要求重新打开，避免索引对应旧内容。

验证使用全部合成数据：7 项测试覆盖随机正反向跳转、跨检查点分段帧、同时间戳边界、原始主机时间、总线设备隔离、504,000 帧分批回放、有界队列、损坏与取消、倍速以及末批完整排空。额外生成 108.36 MiB 合成块文件，索引 434 个检查点约 0.54 秒，跳至 1200.5 秒约 1.16 毫秒，进程峰值 RSS 约 16.5 MiB。这是本机结构化合成测试；数据密集的多通道长文件需要逐帧 CRC 解码，扫描速度会更低，不是对其它机器或真实采样质量的保证。
